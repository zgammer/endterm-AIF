# README for AI assistants (project context)

Read this first. It describes what the project is, how it is built, what the rules are, and how to verify changes. The human-facing README (in Russian) is `README.md`.

**Working language:** the team talks to you in Russian. Reply to them in Russian. All text that appears **inside the book** (chapters, quizzes, UI strings) must be **English**. Code comments may be Russian or English.

## 1. What this is

An interactive web e-book that teaches the *AI Fundamentals* course. It looks like the storybook from the opening of the *Shrek* films: parchment pages, drop caps, heraldic borders. It is plain **HTML + CSS + vanilla JS** (no frameworks, no bundlers, no npm in the shipped project). Version: v0.4, chapters I–IV done (21 pages: 4 + 4 + 6 + 6 + seal).

Experience: a closed book lies on a wooden table. While the user scrolls down, the cover opens, then pages turn one after another like the opening animation. The chapters *are* the pages (nothing below the book). The last page is a "seal" with counters and a locked button. The button unlocks when **all quiz answers are correct OR all hidden signs are found**. Pressing it shows a fake loading bar (about 4 s), then the reward image `img/reward.jpg`.

## 2. File map

```
index.html            GENERATED by build.py. Do not edit by hand.
build.py              header.html + chapters/ch*.html (numeric order) + footer.html -> index.html
partials/header.html  <head>, font switcher, closed-book hero, opens <div id="src" hidden>
partials/footer.html  last page (seal), closes #src, reward overlay, toast, <script>
chapters/chN.html     one file per chapter = a list of <article class="pg"> pages
css/book.css          all styles (paths to images are ../img/...)
js/book.js            progress, quizzes, hidden signs, seal/reward, font switch, page flipping
img/                  hidden-object.png (sign sprite), reward.jpg, + illustrations (see 6)
fonts/                optional user font: mr_AprilraG.ttf|.otf|.woff2

```

Workflow: edit `chapters/` or `partials/`, run `python3 build.py`, then test. Edits to `css/` or `js/` need no build. The site must work when `index.html` is opened from disk (`file://`), so **never use `fetch`, ES modules or anything that needs a server.**

## 3. How the book works (js/book.js)

- All pages (`#src .pg`) are collected once. `layout()` moves the same DOM nodes (no cloning, so listeners and IDs stay valid) into leaves `.lf` inside `#leaves`. A leaf has a front face (right page) and back face (left page).
- Desktop (viewport > 820 px): a spread is 2 pages, page design size 560x740 px. Leaf k: front = page 2k, back = page 2k+1. If `(pages - 1)` is odd, a blank filler page is inserted before the last page. The last page (seal) is always a right page and is never flipped.
- Mobile (<= 820 px): one page at a time, 380x700, each leaf has the page on the front and a blank back.
- Scale to fit the viewport via CSS var `--s`. Scroll mapping: `t = scrollY / (0.9 * innerHeight)`. `t` in 0..1 opens the cover; leaf k turns for `t` in `[1+k, 2+k]`. `hero` height is set in JS to `(1 + flips) * 0.9 * innerHeight + innerHeight`.
- Each turning element uses `transform: perspective(2600px) rotateY(...)` with `transform-origin: left`. z-index is flipped at 50 percent (`100+k` once turned, `100-k` before) so stacking is right. Do not put `transform-style: preserve-3d` on `.bk` (it breaks z-index ordering).
- Page content is clipped to the page (`.pg` is an absolute scroll container). A page that overflows gets an inner scrollbar. Keep pages short enough to fit.

## 4. Content rules for chapters

- A chapter is a sequence of `<article class="pg">` pages. Typical pages: (a) title + drop-cap paragraph + illustration; (b) table or text + illustration; (c) formula box + short code; (d) **"Test of Knowledge" page with 3 questions** (`<h2><small>Chapter N</small>Test of Knowledge</h2>`).
- Quiz markup: `<div class="q" data-a="K"><p>…</p><button>…</button>…<div class="no">hint</div><div class="ex">explanation</div></div>`. `data-a` is the 0-based index of the correct button. Use 3 options. Wrong answers can be retried.
- **Exactly 3 hidden signs per chapter**: `<i class="h" data-n="Beware Ogre"></i>`. Spread them over different pages. Inline ones go inside text or a table cell. For absolute ones add class `a` and position them in the page margin (`right:3px`/`left:3px` plus `top`), so they never cover buttons or text. The sprite is `img/hidden-object.png`.
- Illustration markup: `<figure class="ill" data-f="img/chN-01-name.png"><img src="…" alt="…" onerror="this.parentNode.classList.add('miss')"><figcaption>…</figcaption></figure>`. If the file is missing, a dashed frame shows the file name. Images are shown at a fixed height with `object-fit: cover` (so 4:3 or 3:2 are both fine; 3:2 / 1200x800 recommended).
- Give each chapter an **even number of pages** so the next chapter starts on a right-hand page (chapters I–IV have 4, 4, 6, 6). Quiz pages must still fit after the explanations appear, so keep question texts short.
- Do not give elements IDs inside chapters. Do not add inline scripts. Keep code samples to about 10 lines. Page body font is 15.5 px.
- Tone: short, friendly, slightly fairy-tale, but technically correct. Source of truth: the lecture PDFs listed in section 8.

## 5. State and persistence

- `localStorage["aif-book-v2"] = {found:[…], ok:[…]}`. `found` holds indices of `.h` elements and `ok` holds indices of `.q` elements, **in DOM order**. Inserting or reordering signs/quizzes changes the meaning of saved progress, so when the structure changes, bump the key (for example to `v3`).
- `localStorage["aif-font"]` is one of `classic | april | plain`.
- Totals are counted from the DOM, so new chapters need no counter changes. Unlock rule in `update()`: `found.length >= items.length || ok.length >= qs.length`.

## 6. Fonts and images

- Fonts use CSS variables `--fh` (headings) and `--fb` (body). `html[data-font="april"]` switches to the custom font `mr_AprilraG` loaded from `fonts/` via `@font-face`. The font file is supplied by the user and is not in the repo; without it the fallback fonts are used. Default fonts come from Google Fonts (Uncial Antiqua, IM Fell English), which need internet.
- Optional background images (silently ignored if absent): `img/cover.png`, `endpaper.png`, `parchment.jpg`, `table-wood.jpg`.
- Illustrations: `ch1-01-quest`, `ch1-02-fringe`, `ch1-03-astar`, `ch2-01-landscape`, `ch2-02-restarts`, `ch2-03-annealing` (`.png`), and later `ch3-01-alarm`, `ch3-02-bayes`, `ch3-03-network`, `ch4-01-hidden`, `ch4-02-clues`, `ch4-03-path`, and later `ch5-decisions`, `ch6-clusters`, `ch7-rl`. The user draws them from the prompts in `docs/image-prompts.md`. Do not copy frames or characters from the films (copyright); the art is original, in the style of medieval manuscripts.

## 7. Gotchas that already caused bugs

1. `build.py` only concatenates. If you regenerate `partials/header.html`, keep the whole `<head>` (doctype, meta, font links, `<link rel="stylesheet" href="css/book.css">`). Losing it once produced an unstyled page.
2. In Python, `open(p, "w").write(open(p).read())` truncates the file before reading. Read first, then write.
3. `#src` is `hidden`. Pages only become visible after JS moves them into the book. If JS fails, nothing is shown.
4. Ordering of z-index and 3D transforms is fragile (see section 3). Re-run the browser test after touching the flip code.
5. Do not edit `index.html` directly; it will be overwritten.

## 9. How to verify a change (do this before saying "done")

The user explicitly asked for self-testing before delivery. Static checks are not enough; use a real browser. A working setup: `npm i puppeteer-core @sparticuz/chromium`, launch with `executablePath: await chromium.executablePath()` and `headless: 'shell'`, then open `file:///…/index.html`. Check at 1440x900 and 390x800:

1. No JS errors (`pageerror`). Missing image/font requests are expected until the assets exist.
2. `.pg` count and `.lf` count match expectations; at scroll 0 the closed book is shown.
3. Scroll to `t = 0, 1, 2, …` (`scrollTo(0, t * innerHeight * 0.9)`) and screenshot. Pages must show and nothing may overflow (`scrollHeight <= clientHeight`).
4. Click every sign and every correct answer with **real mouse clicks** at the element centre, and confirm `document.elementFromPoint(x, y)` is that element (this catches overlapped items). Recompute positions after each click, because explanations shift the layout.
5. Counters reach N/N and M/M. Test the unlock rule separately: only signs found, and only answers correct; both must enable the button.
6. Click the button, wait about 5 s, and confirm the reward image loads (`naturalWidth > 0`).
7. Switch the font and confirm `data-font` and the computed font family change.
8. Test with a 4:3 and a portrait illustration substituted for the placeholders.

Do not run `pkill -f chrom` from a shell whose own command line contains "chrom" (it kills the shell).

## 10. Limits and non-goals

The unlock check is client-side and can be bypassed (acceptable for a course book). No backend, accounts or analytics. On phones, dense pages may need inner scrolling. Keep dependencies at zero.
