# AI Instructions: The Book of Magical Algorithms

## About the project

This is a static, interactive web book for the AI Fundamentals course. Course topics are explained through fairy-tale chapters with illustrations, mini-quizzes, and hidden objects. The project uses plain HTML, CSS, and JavaScript—no frameworks or dependency bundlers.

Chapters I–II are currently implemented. The book includes a closed cover that opens as the reader scrolls, animated chapter entrances, browser-based progress tracking, and a final reward.

## Project map

### How the page is assembled

- `build.py` reads `partials/header.html`, then all `chapters/ch*.html` files in numeric order, and appends `partials/footer.html`.
- `index.html` is a generated file. Make changes to the source files (`chapters/`, `partials/`, `css/`, `js/`) and rebuild the page; do not edit the generated HTML manually unless the task explicitly requires it.
- Chapters are `<section id="cN">` elements containing text, illustrations, quiz blocks, and hidden objects.
- HTML paths to stylesheets, scripts, and images are relative to the site root. Preserve this structure so the page works when opened locally and when published as a static site.

## Where to make changes

- Chapter text, formulas, examples, and questions — the corresponding `chapters/chN.html`.
- Shared header, cover, and opening of the main content — `partials/header.html`.
- Book ending, status, counters, final button, and reward overlay — `partials/footer.html`.
- Appearance and responsive layout — `css/book.css`.
- Quiz, hidden-object, progress-saving, and animation logic — `js/book.js`.
- Image names, prompts, and the list of future illustrations — `docs/image-prompts.md`; image files themselves — `img/`.

Do not duplicate functionality across chapters if it is already handled by `js/book.js`. Before changing interactive markup, check which classes, `id`s, and `data-*` attributes are used by the JavaScript and CSS.

## Chapter and interactive-content rules

- Add a new chapter in `chapters/` using the name `chN.html`, where `N` is the next number. The build script automatically includes matching `ch*.html` files in numeric order.
- Use existing chapters as examples for structure, classes, and styling. Keep each chapter's `id="cN"` unique.
- A question is a `.q` block with a `data-a` attribute containing the correct answer's **zero-based** index. Keep the answer buttons, `.no` hint, and `.ex` explanation inside the block.
- Each chapter must contain exactly three hidden `.h` objects. For absolutely positioned objects, use the `.a` class and set their coordinates as in the existing chapters.
- Mark up illustrations using the `<figure class="ill">` pattern. Set the image path in both `data-f` and `img src`; include a meaningful `alt` and a caption. If an image is missing, the existing handler marks its frame accordingly.
- JavaScript calculates the quiz and hidden-object totals from the page elements; do not hard-code the totals.
- The final button unlocks when either all questions have been answered correctly **or** all hidden objects have been found. Do not change this condition unless explicitly requested.
- Progress is stored in `localStorage` under the key `aif-book-v2`. If you change the saved-data format, account for existing progress and explicitly consider backward compatibility.

## Visual style and assets

Maintain the look of a fairy-tale medieval book: parchment, decorative initials, heraldic ornaments, a navy-red-green palette with gold accents, illustration captions, and stylized formula and code blocks. The CSS uses Uncial Antiqua and IM Fell English, with system-font fallbacks.

Illustrations must be original and styled like medieval manuscripts. Do not add film stills, images, or recognizable movie characters. Check `docs/image-prompts.md` for image names and intended uses.

## Build and verification

Run commands from the `aif-book` directory:

```bash
python build.py
```

After changing chapters or partials, run this command to regenerate `index.html`. CSS or JavaScript changes do not require a rebuild. To view the site, open `index.html` in a browser. If the browser restricts local resources, start a local HTTP server from this directory, for example:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`. No automated test setup is currently configured in the project, so manually verify the changed scenarios: page loading, chapter rendering, quiz behavior, hidden-object discovery, progress persistence, and reward unlocking, as relevant to the changes. Check the mobile layout and reduced-motion behavior as well.

## Working on tasks

1. Identify the affected chapter or shared site component, then read the relevant source files.
2. Follow existing components, class names, and coding style; make only changes related to the task.
3. If you change chapter text or interactive markup, rebuild `index.html`.
4. Verify the result in a browser and ensure related flows and progress persistence still work.
5. Do not delete or overwrite user files or unrelated changes. Update these instructions and other documentation if the described structure or behavior changes.
